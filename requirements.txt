# Client-side runtime dependencies for ttsgen / ttsplay / ttsrec / ttsapi.
# Mirrors `[project].dependencies` in pyproject.toml — keep in sync.
#
# This file ships ONLY the lightweight CLI scaffolding: gtts + pyttsx3 (always-
# available engines), pygame (playback), requests + dotenv, sounddevice + numpy
# (microphone capture for ttsrec).
#
# Optional engines are installed separately via the canonical command:
#
#   ttsgen --install pipertts        # piper-tts + voice models from HuggingFace
#   ttsgen --install silerotts       # torch + torchaudio + omegaconf + models
#   ttsgen --install coquitts        # coqui-tts (Idiap fork) + torch + transformers
#   ttsgen --install barktts         # bark (git) + scipy + numpy (~10–15 GB models)
#
# `ttsgen --install <engine>` picks the correct PyTorch wheel index (cpu /
# cu121), respects driver constraints, persists the model directory to
# ~/.config/ttsgen.conf, and verifies download checksums where supported.
# This is the ONLY supported way to add an engine — no [piper] / [silero] /
# [coqui] / [bark] pip extras exist.
#
# Server (ttssrv): runs only via Docker. Build deps live in ttssrv/requirements.txt
# and the two Dockerfiles (ttssrv/Dockerfile for CUDA, ttssrv/Dockerfile-cpu).
#   docker compose up                                    # GPU image
#   docker compose -f docker-compose-cpu.yml up          # CPU-only image
#
# Development install (covers tests + local ttssrv smoke):
#   pip install -e ".[dev]"
# This pulls ruff/black/mypy/pytest plus Flask/marshmallow/uvicorn so
# `pytest` and `python3 ttssrv/app1.py` work without Docker.
